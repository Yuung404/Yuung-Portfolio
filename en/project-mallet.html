CLIENT CONTEXT

Fondation Mallet is a medico-social foundation based in the Yvelines department (78), operating across 11 establishments spread over 3 geographic sites. It supports people with disabilities (intellectual impairment, multiple disabilities, autism spectrum disorders) and employs hundreds of healthcare professionals, educators and administrative staff.

Its ageing and heterogeneous IT infrastructure no longer met the requirements for security, traceability and centralised management. The foundation therefore commissioned our team to carry out a full audit of its information system, followed by the deployment of a modernised infrastructure based on Windows Server 2025 and Active Directory.

PROJECT DESCRIPTION

The Mallet Project is a systems infrastructure project carried out as part of the BTS SIO programme (Year 1). It is structured around 4 progressive missions:

Mission 1 — Infrastructure audit: analysis of the existing setup (hardware inventory, network, services), identification of vulnerabilities and production of a full audit report with recommendations.

Mission 2 — Active Directory deployment: installation and configuration of the Windows Server 2025 domain controller, creation of 3 OUs (ADMIN, PÉDAGOGIQUE, DIRECTION), setup of user accounts and security groups.

Mission 3 — Group Policy Objects (GPO): defining and deploying per-OU policies — access restrictions, encryption, web filtering and hardening of Windows 11 Pro client workstations.

Mission 4 — Supporting services deployment: GLPI (asset management & ticketing), Zabbix (network monitoring), Nextcloud (secure file sharing), PaperCut MF (print management).

MISSION 1 — INFRASTRUCTURE AUDIT (VALIDATED)

The first mission, fully completed and validated, involved producing a comprehensive inventory and assessment of Fondation Mallet's IT infrastructure.

Audit scope:
▸ Hardware inventory — full census of workstations, servers and network equipment
▸ Network architecture — topology, segmentation, interconnection of the 3 sites
▸ Existing services — directory (LDAP), messaging, file shares, print management
▸ Security — access rights analysis, patch management review, practices assessment
▸ Compliance — verification of key ANSSI and GDPR requirements

Key vulnerabilities identified:
▸ No centralised domain controller → uncontrolled account management
▸ No OU-based network segmentation → all users share equivalent rights
▸ No active monitoring (no alerting on failures or incidents)
▸ No ticketing system → IT interventions untracked
▸ Unsecured, non-centrally-backed-up file shares

Adopted recommendations:
▸ Deploy a Windows Server 2025 domain controller with Active Directory (domain mallet.local)
▸ Structure into 3 OUs: ADMIN, PÉDAGOGIQUE, DIRECTION
▸ Deploy GLPI for asset management and helpdesk ticketing
▸ Set up Zabbix for network monitoring and alerting
▸ Deploy Nextcloud for secure internal file sharing
▸ Integrate PaperCut MF for print management

MISSION 2 — ACTIVE DIRECTORY DEPLOYMENT (VALIDATED)

The second mission, fully completed and validated, involved deploying a centralised domain controller to replace Fondation Mallet's ageing infrastructure.

Steps completed:
▸ Server renamed to SRV-MALLET with a static IP assigned (192.168.1.10 / mask 255.255.255.0 / gateway 192.168.1.1 / DNS 127.0.0.1)
▸ AD DS role (Active Directory Domain Services) installed on Windows Server 2025
▸ Server promoted to primary domain controller — domain mallet.local
▸ 3 Organisational Units created: ADMIN, PEDAGOGIQUE, DIRECTION
▸ 3 security groups created: GRP-ADMIN, GRP-PEDAGOGIQUE, GRP-DIRECTION
▸ User accounts created (a.systeme, p.educateur, m.directrice) and assigned to their respective groups

Outcome:
The mallet.local domain is fully operational. All users are organised by profile with rights matched to their role, in line with the audit recommendations from Mission 1.

MISSION 3 — GROUP POLICY OBJECTS (GPO) (VALIDATED)

The third mission, fully completed and validated, aimed to secure and control client workstations according to user profiles via GPOs targeted at each Organisational Unit.

GPO-ADMIN — Hardened password policy:
▸ Minimum length: 12 characters
▸ Complexity enabled (uppercase, digits, special characters)
▸ Password expiration: every 90 days
→ Administrators have full system access — their accounts require maximum protection.

GPO-PEDAGOGIQUE — System rights restrictions:
▸ Registry editing tools blocked
▸ Control panel access restricted
→ Educators don't need to modify the system — this limits the risk of accidental or intentional changes.

GPO-DIRECTION — Sensitive data protection:
▸ All removable storage devices (USB) fully blocked
→ Management handles patient files and HR data — blocking USB prevents data exfiltration (GDPR requirement for a medico-social foundation).

Outcome:
Each user profile has restrictions suited to their access level. All 3 GPOs are linked to their respective OUs and applied automatically at every login.

TARGET ARCHITECTURE

The target infrastructure is built around an Active Directory domain mallet.local managed by a Windows Server 2025 domain controller. Three Organisational Units (OUs) structure access management:

OU ADMIN — System administrators, full access rights, administration tools and rights management GPO.

OU PÉDAGOGIQUE — Teachers and educators, restricted access to educational resources, web browsing filter applied via GPO.

OU DIRECTION — Directors and HR staff, access to confidential data, data encryption GPO and external device restrictions.

EXPLANATORY GUIDE — UNDERSTANDING EACH ACTION

A plain-language breakdown of each action taken — what was done, why, and how to interpret the result.

01 — RENAMING THE SERVER

Changed machine name from WIN-XXXXXXX to SRV-MALLET via Server Manager → Local Server. A server needs a clear, identifiable name on the network — SRV = server, MALLET = project. Like labelling a box.

02 — STATIC IP ADDRESS

Manually configured 192.168.1.10 on the network adapter. A server must never change address — if it did, clients wouldn't know where to find it. The static IP is the server's permanent address on the network.

03 — INSTALLING THE AD DS ROLE

Added the AD DS role via Server Manager → Manage → Add Roles and Features. Roles are activatable modules — AD DS turns the server into the network's central manager, handling all users, machines and access rights from one place.

04 — PROMOTING TO DOMAIN CONTROLLER

Created a new forest with domain mallet.local via the AD DS post-install wizard. Installing AD DS lays the foundations; promoting the server builds the house. The domain is the territory this server controls — its own country with its own laws.

05 — CREATING THE OUs

Created ADMIN, PEDAGOGIQUE, DIRECTION in Tools → AD Users and Computers → right-click → New → Organisational Unit. An OU is a folder for organising users by profile. Without OUs, everyone shares the same rights — a major security flaw.

06 — SECURITY GROUPS

Created GRP-ADMIN, GRP-PEDAGOGIQUE, GRP-DIRECTION inside each OU. A security group is the bridge between users and their rights — assign rights to the group once, and every member inherits them automatically. Like a shared access badge.

07 — USER ACCOUNTS

Created a.systeme (ADMIN), p.educateur (PEDAGOGIQUE), m.directrice (DIRECTION) and added them to their groups. Each employee gets an access badge matching their role — placing them in the right OU makes them automatically inherit the correct rules.

08 — GPO-ADMIN: PASSWORD POLICY

GPO editor linked to OU ADMIN: min. 12 characters, complexity enabled, 90-day expiration. Admins have access to everything — their password must be as strong as a 12-digit safe combination, not "1234".

09 — GPO-PEDAGOGIQUE: SYSTEM RESTRICTIONS

User configuration → Administrative Templates: registry tools and control panel blocked. Educators don't need to modify the system — give them the classroom key, not the server room key.

10 — GPO-DIRECTION: USB BLOCK

Computer configuration → Administrative Templates → System → Removable Storage Access: all removable devices blocked. Management handles patient files and HR data — without this, anyone could plug in a USB and copy everything in 2 minutes. GDPR obligation for a medico-social foundation.
