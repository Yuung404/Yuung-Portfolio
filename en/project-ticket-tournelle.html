CONTEXT & PROBLEM

At the school, technical incidents are reported through Excel, text messages, WhatsApp voice notes or phone calls. The result: lost requests, delays, no figures for management and overloaded IT staff. Ticket'Tournelle is a web portal where every staff member reports an incident and follows its resolution, technicians handle tickets, and management reads indicators.

The client sets 9 constraints, including a named account per person, a French and English interface, an in-house server that we install and run ourselves, and admin accounts managed according to ANSSI guidelines.

WHAT I BUILT

1. Specification and mock-ups
Needs analysis, specification, user stories, ticket lifecycle (open, assigned, on hold, resolved, closed), categories and priorities, then 12 screen mock-ups for the three roles: user, technician and administrator.

2. Database
Conceptual and logical models, then 13 MariaDB tables with constraints and indexes, and 5 SQL views for the dashboard. I added 4 tables justified by the specification: rooms, allowed status transitions (any other change is rejected), one-time password reset, security log. Bilingual labels, Argon2id hashes, accounts disabled rather than deleted, least-privilege application SQL account.

3. In-house web server
Debian 13 VM with no desktop, root disabled in favour of a named sudo account. The whole setup is automated in a re-runnable provision.sh: Apache and PHP 8.4, MariaDB listening locally only, HTTPS with TLS 1.2 / 1.3, security headers, UFW firewall (22, 80, 443), Fail2ban, key-based SSH, automatic security updates, nightly database backup. Two test scripts check the database and the server's security.
